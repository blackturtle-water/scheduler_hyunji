[2번 사이트 업데이트 내역]
버전: 20260730-hyunji-6
대상 APP ID: scheduler_hyunji

1. 첫 화면 변경
- 사이트 접속 시 기본 화면이 대시보드가 아니라 [달력 일정] 화면으로 열리도록 수정했습니다.
- index.html의 기본 활성 메뉴/패널도 달력으로 맞췄습니다.

2. 날짜 선택 일정 목록 기능 유지 및 보강
- 달력 날짜 클릭 시 바로 일정 추가창이 뜨는 방식이 아니라, 해당 날짜의 일정 목록 확대창이 열리도록 유지했습니다.
- 일정 목록 최하단에 [이 날짜에 일정 추가] 버튼을 유지했습니다.

3. 2번 사이트 전용 저장소 구조 유지
- 기존 scheduler_hyunji APP ID 구조를 유지했습니다.
- localStorage key, Gist file name, 공휴일 캐시, 자동 동기화 상태값, 삭제 기록도 scheduler_hyunji 전용 prefix를 사용합니다.
- 1번 사이트 데이터와 섞이지 않도록 분리 구조를 유지했습니다.

4. 자동 동기화 기능 추가
- GitHub PAT와 Gist ID를 최초 1회 저장한 뒤 병합 동기화, 업로드, 불러오기를 한 번 실행하면 이후 자동 동기화가 활성화됩니다.
- 일정/할 일/메모/D-Day 변경 시 약 2.5초 후 자동 병합 동기화가 실행됩니다.
- 사이트 실행 시, 화면 재진입 시, 온라인 복귀 시, 약 30초 주기로 클라우드 내용을 자동 확인합니다.
- 자동 동기화는 수동 알림창을 띄우지 않고 상단/사이드바 상태 표시로만 안내되도록 구성했습니다.

5. 병합 동기화 및 삭제 동기화 보강
- 서로 다른 기기에서 추가된 데이터는 자동 병합됩니다.
- 같은 ID의 데이터가 양쪽에서 수정된 경우 updatedAt 기준 최근 수정본을 우선합니다.
- 삭제된 항목이 다른 기기에서 다시 살아나는 문제를 줄이기 위해 삭제 tombstone 기록을 추가했습니다.
- 동기화 데이터에 appId, deletedIds, syncVersion 필드를 포함하도록 보강했습니다.

6. 공휴일 자동 표시 개선
- 대한민국 공휴일 JSON 데이터를 자동으로 불러와 달력에 표시합니다.
- 설날, 추석, 대체공휴일 등 연도별 공휴일 데이터가 캐시되어 재접속 시 빠르게 표시됩니다.
- 현재 보는 연도에 공휴일 데이터가 없으면 다시 불러오도록 보강했습니다.
- 네트워크 오류 시 기본 양력 공휴일을 임시 표시합니다.

7. 캐시 버전 업데이트
- index.html의 style.css, github-sync.js, app.js 버전을 20260730-hyunji-6으로 갱신했습니다.
- GitHub Pages 배포 후 브라우저 캐시로 예전 파일이 뜨는 문제를 줄였습니다.

[사용 방법]
1. 기존 2번 사이트 파일을 먼저 백업합니다.
2. ZIP 안의 index.html, app.js, github-sync.js, style.css, README.md를 2번 사이트 저장소에 덮어씁니다.
3. GitHub Pages 배포 후 사이트에 접속합니다.
4. 설정 및 동기화 메뉴에서 PAT와 Gist ID를 저장합니다.
5. 기존 클라우드 데이터를 쓰는 기기라면 먼저 [클라우드 불러오기] 또는 [병합 동기화]를 한 번 실행합니다.
6. 이후부터는 일정 변경 시 자동 업로드/자동 불러오기/병합 동기화가 작동합니다.

[주의 사항]
- 여러 기기에서 같은 일정을 동시에 수정하면 최근 수정 시간이 더 늦은 데이터가 우선됩니다.
- GitHub Gist API를 사용하는 구조라 너무 짧은 주기의 실시간 동기화는 피하고, 약 30초 주기로 자동 확인하도록 구성했습니다.
- PAT와 Gist ID는 브라우저 localStorage에 저장됩니다. 공용 PC에서는 사용 후 토큰 관리에 주의하세요.
